## Browser support limitations (binding)

- Offline availability is best-effort. Browser storage may be evicted; never
  promise indefinite durability. A character is shown "Available offline" only
  after a compatible projection snapshot is committed AND the controlling worker
  confirms its build cache — readiness is eviction-aware.
- Where Web Locks are unsupported, sheets remain read-only with an explanation;
  no unsafe editing is offered. No timeout-based lock stealing: one
  editing/synchronizing tab per character; takeover quiesces the owner first.
- A never-settling transport is still bounded: Task 6 added a 30 s abort that
  preserves the frozen request bytes and treats timeout as an uncertain outcome
  (immutable retry with the same key), per the uncertain-outcome protocol.
- `SWEETROLL_TEST_AUTH=1` is a test-only escape hatch for the production
  offline fixture (defaults OFF; no production UI affordance). Never set it
  outside local/CI acceptance runs.
- Offline writes are field sets and direct resource bumps only. Actions,
  creation, archive/recovery, migration and authoritative export require
  connectivity. Discarding an uncertain attempted command is not server
  cancellation; expiry (>30 days) requires manual review, never automatic
  new-key retry.
