### Notes on the negative paths

- **Step 7 (over-budget):** The added expression source `1+1+1+…+1` (128 `+` signs, 257 AST nodes) exceeds `PACKAGE_LIMITS.expressionAstNodes` (256). `saveDraft` succeeds with `assessment.ok=false` (the document structurally decodes; the compile step would fail), and `publish` re-runs `assessDocument` → `compileDocument` → fails compile → returns `invalid_package` carrying a `limit_exceeded` diagnostic. The brief's described mechanism (`effectiveLimits.maxAstNodes = 1` set in the package) is functionally equivalent: in both cases the AST exceeds the effective budget. We hit the budget via the platform `PACKAGE_LIMITS` ceiling because `compileDocument` always sets `effectiveLimits` to `PACKAGE_LIMITS` (see `src/systems/implementation/rules/compile-document.ts:91`), so a hand-crafted package with reduced `effectiveLimits` would have its values overwritten before publish. Either way, the user-visible result is `422 invalid_package` with `limit_exceeded`.
- **Step 8 (breaking change):** The original system's draft is replaced with a document that omits the `proficient` field (revision 2 → 3). `publish` calls `comparePackages` against the already-published `1.0.0` and returns the report's `breaking_removed_definition` finding as an `invalid_package` diagnostic. Step 8 is exercised on the original system (not the clone) because the clone has no prior published version; `comparePackages` only runs when a previous version exists (`src/systems/authoring.ts:472`), so the breaking-change gate is bypassed for first publishes by design.
