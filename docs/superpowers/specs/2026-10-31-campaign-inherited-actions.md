# Campaign inherited actions contract

Status: implemented in PR #25; draft-preservation fix `f11e7b9` passes all CI #154 checks. Normal hosted and backend boundary acceptance passed on `5d3bb88`; final offline GUI acceptance awaits redeployment of the repair. Authority: [execution plan](../plans/2026-10-31-campaign-inherited-actions.md).

Create keeps the existing campaign/kind/content/revision/key envelope and adds optional `baseTemplateId` (definition ID, at most 64 characters). Content contains name (1–200, nonblank), description/notes (0–2000), item defaultQuantity (positive safe integer), and optional `defaultValues` (at most 100 existing writable base fields). Values use the published field types and bounds; computed/image fields cannot be supplied. Blank templates reject defaultValues. No actions, expressions, seeds, snapshots, schema or version selectors are accepted.

The server reads the campaign pin through the injected Systems published-package capability. Stored content additionally contains immutable `base: {versionId, packageChecksum, templateId}`. Edit accepts presentation/defaultValues only; the server retains base and kind, validates defaults and appends a content revision. Omitting defaults resets to base defaults. Archive/recover advances resource revision only. Existing 500-template and 100-row page bounds apply. Base choices are GM-only, authorized against the active campaign, and contain kind, label, field constraints/defaults and existing action summaries; they disclose no new authoring authority.

Placement remains reference-only: campaign/template IDs plus exact resource/content revisions, null templateId and empty values. Under existing campaign → character locks, current lifecycle/revisions and campaign/character pin are checked. The server materializes a snapshot. Data-only snapshots remain `{kind, values: {name,description,notes}, quantity?}`. Derived snapshots add strict `base` and `defaultValues`; metadata values never enter expression bindings. Entry values contain all writable typed defaults; quantity remains separate. The snapshot is server-owned, immutable provenance; update commands accept only declared typed instance values and quantity. No snapshot/base/source edit is accepted.

The effective-definition resolver returns the immutable system definition for system entries and validated derived snapshots, or no definition for personal/blank entries. It verifies pinned version/checksum, kind, source and field/default shapes, target entity sheet/slot applicability and expression field dependencies. Projection, edit validation, action lookup and push use this result. No synthetic package compilation or live catalog lookup occurs during play. Invalid derived state fails explicitly; unsupported/missing dependencies reject discovery/placement rather than dropping actions. Declared entry fields alone override character bindings.

Projection embeds a bounded definition summary on each derived entry: id/label/kind, flat writable field constraints/defaults, and action id/label/kind/input summaries. Expression IDs, policies and executable definitions remain server-owned; projection excludes them. This supplies resolved writable fields and action summaries, so returned sheets and current offline snapshots require no catalog fetch. Labels come from snapshot metadata; a base field called name stays independent. Catalog edits affect new copies only; archive leaves placed copies usable. Authorized return/duplication preserves snapshots and independent values but conveys no former catalog/history access.

Push context retains base definition ID, version/checksum, entry/slot and exact placed campaign source. Existing audience, placement generation, lineage, limits, locks and receipt authorization remain mandatory. Metadata/default edits on the catalog do not change a copy; removal blocks execution/push. Exact restoration and return/adoption follow the existing push contract. Frozen original bindings determine rerolls despite instance edits.

Bad input/base/defaults: 400; unauthorized/not found: existing 403/404 policy; stale revisions/lifecycle/pins: 409; catalog/payload limits: 413; invalid persisted derived state: existing invalid_state/invalid_package mapping. Exports retain server-owned base/defaults and snapshot provenance, never executable client definitions. Existing current-account cache scope/purge, reference freezing, offline entry queue and durable online push attempts are reused. No offline push queue, version conversions or migration work is introduced.
