# Named dice groups — slice B contract

Status: implementation contract, after merged slice A (`740204f`). No push/reroll command is introduced.

Document/package minor version **1.1** enables expression grammar **0.2**. Existing 1.0 documents, compiled expressions, checksums, receipts and RNG draw order remain unchanged. The existing V1 TypeScript/schema names denote the major version; decoders explicitly accept 1.0 and 1.1 and reject unknown versions. Export envelopes remain version 1 and preserve the enclosed package version. Clone/render/import never downgrade 1.1. Old clients reject the new package version rather than misinterpreting groups. Editing a grouped formula explicitly promotes the working document to 1.1; it never republishes or mutates a published version.

Grammar 0.2 adds `group("attribute", "Attribute", dice(fields.attribute, 6))`. IDs use the existing definition-ID vocabulary and are unique per expression; labels contain 1–120 characters. The wrapped operand is direct dice (or static keep-high/low dice). `countSuccesses(group(...), 6)` counts that group's dice, while a bare group sums them. Normal arithmetic composes terms and thresholds can differ across groups. No global interpretation flag, collection traversal, scripting or automatic effects. Counts of named groups are deterministic scalar expressions. At most 32 named dice groups; anonymous groups remain bounded by the AST and dice ceilings; platform/package dice and side ceilings apply across all groups including anonymous dice and empty groups.

Compiled dice nodes optionally carry `{group:{id,label}}`; expressions using them carry `languageVersion:"0.2"`, admitted only in package 1.1. Legacy expressions omit both additions byte for byte. A successful grouped roll keeps `total`, `expression` and flat `dice`, and adds a bounded `breakdown` version 1.0 containing ordered groups and a calculation graph. Groups record label, evaluated count, sides, sum/success/keep operation, threshold when applicable, dice IDs and subtotal. Every die in this result has a stable group-scoped ID and group ID; counted dice also carry success status. Anonymous groups receive reserved `@<AST path>` IDs, never inferred historical identities.

Calculation terms record a stable AST-path ID, operation, operand IDs and evaluated scalar value. References, literals, arithmetic/functions and dice reductions remain distinct. The root term explains the factual total; count expressions appear as operands of their reduction, not as extra successes. This preserves group identity under nesting, mixed sum/count, subtraction and scaling. Evaluation visits left-to-right, arguments in authored order, count before dice, dice in index order; keep ties retain generation order. No extra RNG calls are made for metadata. IDs are stable within a saved roll and are not globally unique roll IDs.

Only the authoritative evaluator constructs outcomes. Requests still carry action inputs, expected revision and idempotency key; client dice, totals, IDs and breakdowns are rejected by existing strict request schemas. The existing audience/replay authorization applies to the complete result, including breakdown. A new nullable JSONB column stores breakdown beside dice in `character_rolls`; old rows stay NULL, old result/receipt JSON is not rewritten. Receipts, campaign export and authorized history must preserve this structure. Legacy displays fall back to the existing flat dice representation. Upgrades/rollback use their existing pinned-package/state migration semantics and retain historical rolls.

The shared player/GM/preview renderer uses text labels, thresholds, kept/discarded and success/failure state rather than color as the sole distinction. Guided authoring uses existing field/input choices and updates the same formula AST/source, while unsupported custom structures stay in the custom editor. Production-offline caches may retain old packages; new clients decode both, old clients must fail clearly on unsupported versions. Acceptance must cover imports/clones/publish, both action sources, persistent/replayed results, audience/export filtering, upgrade/rollback and reload/offline paths in addition to deterministic evaluator tests.
