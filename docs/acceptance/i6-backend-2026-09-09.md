## Accepted here (backend only)

1. **Four-player session bursts over ordinary HTTP**
   (`tests/integration/campaign-load.test.ts`, 2 tests): campaign
   provision → invitation/review/accept ×3 → 8 campaign sheets with all
   four members as controllers → 120 concurrent reads, 12 content
   writes (GM handouts + player diaries), 32 bumps in 4 rounds, 64
   campaign-audience rolls (every actor × every sheet × 2), same-key
   bump/roll replays returning `replayed: true` with zero new rows.
   Exactly-once verified in SQL: per-sheet revision `base+4`, health
   `base-4`, 8 stored rolls per sheet, per-actor burst receipts 24/24/24/24
   all `completed`, 12 content rows, bounded lists reject `limit=101/0`
   with 400.
2. **Load distributions (reported, assertions not weakened)** under
   existing test conditions (`app.inject`, local PostgreSQL, concurrency 8):
   reads p95 26.7 ms (n=120), content writes p95 77.7 ms (n=12), bumps
   p95 168.4 ms (n=32), rolls p95 139.8 ms (n=64) — ordinary ≤300 ms,
   rule actions ≤500 ms, with margin.
3. **Removal/return at supported limits**: roster filled to `maxMembers`
   100 (owner + 3 invited + 96 seeded); HTTP pagination walks 100/100
   unique across 4 bounded pages; over-limit accept denied as `conflict`
   with no membership row; character cap denied as `bad_request` at the
   placement seam; 20 campaign-created sheets + 1 adopted sheet;
   GM-removes-player returns the adopted sheet (`ownerId`, null
   `campaignId`, exact pin) while campaign sheets stay attached
   (GM 200 / removed 404); rejoin reactivates generation 2 → 3 and
   restores reads.
4. **Secret absence**: invitation tokens persist as `sha256` hash only;
   receipts and audit never carry token bytes or the hash
   (`campaign-invitations.test.ts`, 17 tests); the authoritative roll
   secret is consumed only as an RNG seed (`src/systems/runtime.ts:350`)
   and never logged or returned; no `console`/logger token call sites
   exist in `src/`.
5. **Migrations**: production upgrade path green (`migrations.test.ts`,
   9 tests incl. 0012–0016 campaign tables, hash-only invitation storage,
   ownership union); rollback injection green — character migration
   rollback suite (`character-migration.test.ts`, 23 tests) plus the
   throwing-hook removal rollback (`campaign-membership.test.ts`).
6. **Characters bypass paths re-verified** by existing suites (all green
   in the full `test:integration` run, 27 files / 290 tests):
   `campaign-character-authorization` (30), `character-replay-authorization`,
   `character-http-acceptance` (7), `system-authoring`.
